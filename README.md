# Pickaxe Pals

Working title. A cute mining incremental for Roblox: mine ore, sell it, hatch pets that mine for you, and rebirth for permanent bonuses.

The code lives here as plain files. [Rojo](https://rojo.space/docs/v7/) syncs them into Roblox Studio.

## One-time setup

1. Install Git and VS Code. VS Code will offer the recommended extensions (Luau language server and StyLua).
2. Install [Rokit](https://github.com/rojo-rbx/rokit), then run `rokit install`. `rokit.toml` pins the versions of Rojo, StyLua, Lune, Wally and run-in-roblox this project uses.
3. Install the Luau packages: run `wally install`. It reads `wally.toml` and fills in `ServerPackages/`, which is ignored by Git because it is rebuilt from the manifest.
4. Install the Rojo plugin in Roblox Studio. `rojo plugin install` does this, or follow the [Rojo installation guide](https://rojo.space/docs/v7/getting-started/installation/).
5. Start syncing. Run `rojo serve` in this folder. In Studio, open a new Baseplate place, then use Plugins > Rojo > Connect.
6. Turn saving on for that place: Game Settings > Security > **Enable Studio Access to API Services**. A published test place needs this, and so does a local server in Studio. Without it a joining player is kicked with `Could not load your save.` — or set `useMockInStudio` in `src/shared/Config.luau` to true for a playtest that does not save at all.

## Check that setup works

- Press Play in Studio. The Output window should show `Pickaxe Pals server started. A free player finishes in 21.1 days (the model says about 21).`, `Saving player profiles as PickaxePals_PlayerData with ProfileStore.`, one `[WorldBuilder] <name> is a <ore> node` line for every ore node it found and one `[WorldBuilder] <name> is a Sell Pad` line per pad, `Sunny Burrow is live: hold on an ore node to mine it, stand on the Sell Pad to sell.` and `Pickaxe Pals client started. Hold on an ore node to mine it.` Anything it does not adopt, it names in a warning at startup: a `kind` it does not know, an `oreId` that does not exist, or an `oreId` with no `kind` at all.
- Change the text in `src/server/Main.server.luau`, save, and press Play again. The new text should appear.
- Run `lune run tests/run`. It should end with `All tests passed.`
- Run the smoke test inside real Roblox: `rojo build -o build/PickaxePals.rbxl`, then `run-in-roblox --place build/PickaxePals.rbxl --script tools/studio_probe.luau`. It must end with `RESULT failures= 0`. Close Studio first, and note that `--place` is required even though the help calls it optional.
- Run `stylua src tests tools` once to apply the project's formatting.

## Author the layer, then play it

Nothing in the world is generated by code: you place the objects in Studio and the server plays what it finds. A part or a model says what it is with a **`kind`** attribute, which is set in the Properties panel's Attributes section; anything without one is decoration, and the server leaves it alone. The Output window lists everything it adopts, and warns by name about anything it cannot.

### Placeable objects

| Property | Accepted values | What it results in |
| --- | --- | --- |
| `kind` | `"ore"` | A mineable node. Hold on it to mine; when it breaks it pays one ore into the backpack, goes dark and comes back after that ore's `respawnSeconds`. |
| `kind` | `"sellPad"` | A Sell Pad. Standing on it sells everything in the backpack. A place may have as many as it likes, and each one buys. |
| `kind` | anything else | Nothing is adopted, and the warning names the two values that work. |
| `kind` | *(not set)* | Decoration: never adopted, and never warned about. |
| `oreId` | `"pebblePop"`, `"copperDaisy"`, `"honeyQuartz"` | Which ore a node is. Health, value and respawn time all come from that ore in `Config.layers`. Required when `kind = "ore"`. |
| `oreId` | anything else | Nothing is adopted, and the warning lists the ids that exist. |
| `unlimited` | `true` | Only on `kind = "ore"`. The node pays out and is ready again on the very next hit, so it never runs dry: a test ore that needs no waiting. |
| `unlimited` | `false` | *(the default)* The node breaks, goes dark and returns after `respawnSeconds`. |

Written by the server, and not for authoring: `nodeId` (what the client sends back when you aim at the object), `health` and `maxHealth` (what a health bar reads). A `nodeId` set by hand is honoured, if you want an id that survives a rename.

A node may be a `Part` or a `Model`, so a cluster of rocks can be one node: set `kind` and `oreId` once, on the model, and its parts are what goes dark and what pays out. Its position is its `PrimaryPart`'s, or its first part's when it has none, and `Config.mining.nodeRangeStuds` is measured from there. A `kind` inside an object that already has one is not examined again, so the outermost object wins.

Everything else is yours: colour, size, position, material, how many parts a model has. Keep placed objects anchored: anchoring is not what makes a node findable, but an unanchored rock is one physics can carry away mid-swing.

There is no `kind` for the layer doors yet, and that is deliberate: the table in [src/shared/Properties.luau](src/shared/Properties.luau) holds only what something actually reads, and a property that appears to work but does nothing is worse than a property that does not exist yet. Adding one is an entry in `Properties.kinds` plus the code that reads it.

- Hold the mouse button (or your finger) on an ore node to mine it. Pebble Pop breaks in three hits with the starter pickaxe and pays 8 coins. Copper Daisy and Honey Quartz take longer and pay more.
- A broken node drops one ore into the backpack and grows back a few seconds later. The backpack holds 50 ore to start.
- Stand on the Sell Pad to sell everything you carry. There is no button: walking on is the whole interaction, which is also how auto-sell will work later.
- The two buttons in the top-left panel buy the next pickaxe (faster hits, more damage) and the next backpack (more room). The first pickaxe costs 120 coins, which is about 25 seconds of mining, so the first upgrade lands inside the design document's 30-second target.

Coins, the pickaxe tier and the backpack level are saved, so leaving and rejoining keeps them. The ore in the backpack is not saved: it is one trip to the Sell Pad, and the architecture document saves progress, not the contents of your pockets. The server decides every number: how far away you may mine from, how fast your pickaxe tier is allowed to hit, how much damage a hit does, and what an upgrade costs. The client only asks, so a modified client cannot mine faster or from further away.

## Saving

One profile per player, in the DataStore named by `Config.saving.storeName`, held by [ProfileStore](https://madstudioroblox.github.io/ProfileStore/) (installed with Wally). `Schema` owns the shape of the profile and `DataService` owns when it is read and written.

- **What is saved** is the architecture document's `PlayerData`: coins, gems, rebirths, pickaxe tier, backpack level, pets, equipped list, per-egg pity counters, the daily streak and quest counters, the last seen time, recent purchase ids, and flags.
- **When**: the store autosaves on its own schedule, saves when a player leaves, and saves when the server shuts down. Ordinary play does not save on every coin — `DataService.save` is for the moments that must not be lost, which will be purchases and their receipt ids.
- **One server at a time**: the store locks a profile while it is in use, so two servers cannot write the same player. If another server takes the profile, the player is asked to rejoin instead of playing on with data that is no longer being saved.
- **The profile is loaded before the player can act.** Every request path reads the profile through `DataService.get`, which returns nothing until the load finishes, so an early click is dropped rather than applied to the wrong data.
- **Old saves keep working.** A profile carries `Schema.version`, and `Schema.upgrades` runs the upgrade functions in order from the version it was written with, so a v1 save opens in v2 once that exists. A save written by a *newer* build is refused rather than downgraded, and a damaged one is repaired field by field: numbers are clamped to their real range, wrong types fall back to the template, and anything a DataStore cannot hold is dropped.

Only a running Roblox server can prove the production DataStore round trip, so the last check stays a person's: publish the place, play, note your coins, leave, rejoin, and see them again. `tools/studio_probe.luau` covers the part that can be automated: driven by run-in-roblox it loads every module, places a small world by hand and runs a save-then-reload through ProfileStore's in-memory store inside a real place, which is where the profile whitelist is checked. It cannot reach the real DataStore, and it says so rather than hiding it: it prints `DataStoreState`, the verdict ProfileStore sets for itself when it loads. On a place that is not published that reads `NoAccess`, a direct call fails with `You must publish this place to the web to access DataStore.`, and ProfileStore still hands out a working session, so a playtest can look healthy while nothing is being saved.

## Folders

```
default.project.json   maps the folders below to Roblox services, including ServerPackages
wally.toml             the Luau packages this project installs, and wally.lock pins them
src/shared/            code used by both sides: Config (balance numbers), Properties (the
                       placeable-object vocabulary: the kinds, the values they accept and the
                       readers for them), Formulas (game math), Schema (the saved profile:
                       shape, version, upgrades), Types (data shapes) and RateLimiter. Nothing
                       here calls Roblox services, so the tests can load it.
src/server/            server scripts. Main starts the rest: DataService (loading, saving and
                       releasing profiles), WorldBuilder (finds the ore and the pads), State
                       (what the client may see), MiningService (hits) and EconomyService
                       (selling and upgrades)
src/client/            client scripts: Hud (coins, backpack and upgrade buttons) and Main
                       (aiming, hold-to-mine and the remotes)
tests/                 tests for code that runs without Studio, run with Lune
tests/support/         a stand-in for ProfileStore and for the Roblox globals, so the saving
                       lifecycle can be tested outside Studio
ServerPackages/        installed packages, rebuilt by `wally install`, ignored by Git
tools/                 the Studio smoke test that run-in-roblox runs inside a real place
stylua.toml            formatting rules
```

## Notes

- `src/shared/Config.luau` mirrors the economy spreadsheet. Change both together until the config is generated from the spreadsheet.
- Files in `src/shared` that the tests load must not call Roblox services, so they can run outside Studio.
- The tests drive the real `DataService` against a stand-in ProfileStore, which is how the shutdown path the document calls a launch risk is covered without a live DataStore. `tests/world.luau` runs the real `WorldBuilder` on Lune's Instances, so which objects are ore, which are pads, what a model does differently from a part and what a mistyped property is told are all checked without opening Studio.
- Pets, eggs, rebirth, the layer doors and the other three layers are not built yet. Sunny Burrow with saving is the whole playable slice, and every object it needs is placeable today: ore nodes and Sell Pads.
